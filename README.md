## 2. 문제 정의

> 일정 관리 앱은 많지만, 쓰려고 할 때마다 제목·날짜·시간을 칸에 맞춰 직접 입력해야 한다.<br/>
> 바쁠수록 이 과정을 건너뛰게 되고, 할 일은 메모장과 메신저에 흩어진 채 마감 직전에야 다시 떠오른다.<br/>
> 막상 정리해도 **언제 할지를 정하는 일은 여전히 사람의 몫**이다.

### 🔍 문제를 두 단계로 나누면

| 단계 | 사용자가 겪는 어려움 | 틈 플래너의 해결 |
| :---: | --- | --- |
| **① 기록** | 칸마다 직접 입력해야 해서 번거롭고, 결국 기록을 미루게 됨 | 문장 그대로 적으면 **AI가 항목별로 정리** |
| **② 배치** | 정리된 할 일을 언제 할지 매번 직접 판단해야 함 | **스케줄링 알고리즘이 빈 시간에 자동 배치** |

### 👥 대상 사용자

- 과제, 시험, 아르바이트 등 바쁜 일정에 약속이 뒤섞인 **대학생**
- 일정이 자주 바뀌는 **1인 작업자(프리랜서)**

### ⚖️ 기존 서비스와의 차이

| 구분 | 기존 AI 일정 서비스 (Motion, Reclaim 등) | 틈 플래너 |
| --- | --- | --- |
| 언어 | 영어 중심 | **한국어 자유 입력** |
| 비용 | 주요 기능이 유료 플랜 중심 | 무료 오픈소스 |
| 입력 방식 | 정해진 양식 위주 | 대충 쏟아낸 메모 그대로 |
| 배치 근거 | 왜 그 시간에 넣었는지 설명이 부족 | 블록마다 **배치 이유**를 함께 표시 |

> 💬 예: *"마감이 가장 급해서 오늘 저녁에 넣었어요"*

## 3. 핵심 기능

### ✍️ 기능 1. 막 적기 — AI 정리

"내일 3시에 치과, 주말에 장보기"처럼 자유롭게 입력하면, AI가 항목마다 **제목 · 종류 · 마감 · 예상 소요시간 · 우선순위**를 뽑아 정해진 JSON 형식으로 돌려준다. 사용자는 저장 전에 결과를 확인하고 직접 고칠 수 있다.

<details>
<summary>입력과 출력 예시 보기</summary>

```text
입력: 금요일까지 운영체제 과제, 내일 3시에 치과, 주말에 장보기
```

```json
[
  { "title": "운영체제 과제", "type": "task",  "deadline": "금요일",    "duration": 180, "priority": "high" },
  { "title": "치과",          "type": "event", "start": "내일 15:00", "duration": 60 },
  { "title": "장보기",        "type": "task",  "deadline": "주말",      "duration": 60,  "priority": "low" }
]
```

</details>

### 🧩 기능 2. 자동 스케줄링

**고정 일정(수업, 약속)을 피해** 빈 시간대에, 마감 임박도와 우선순위가 높은 할 일부터 채워 넣는 알고리즘을 직접 구현한다. 긴 작업은 여러 블록으로 쪼개고, 일정이 바뀌면 다시 배치한다.

### 📅 기능 3. 캘린더와 배치 이유

주간·월간 캘린더에 결과를 보여 주고, 블록마다 왜 그 시간에 배치했는지 한 줄 설명을 붙인다. 블록을 드래그해 옮기면 나머지 일정도 함께 조정된다.

### 💡 설계 원칙: AI와 알고리즘의 역할 분담

```mermaid
flowchart LR
    A["✍️ 자유 입력"] --> B["🤖 AI 정리<br/>(Gemini API)"]
    B --> C["✅ 사용자 확인 · 수정"]
    C --> D[("🗄️ DB 저장")]
    D --> E["🧩 스케줄링 알고리즘"]
    E --> F["📅 캘린더 + 배치 이유"]
```

| 담당 | 하는 일 | 이유 |
| :---: | --- | --- |
| **AI** | 문장을 이해하고 항목으로 정리 | 자연어 해석은 규칙으로 처리하기 어려움 |
| **알고리즘** | 빈 시간 계산과 실제 배치 | 같은 입력이면 같은 결과가 나와야 하고, 일정 겹침이 없어야 하며, **테스트로 검증**할 수 있어야 함 |

| :---: | --- | --- |
| **프레임워크** | Next.js + TypeScript | 기존 JS 경험을 살릴 수 있고, 화면과 API를 한 프로젝트에서 관리해 1인 개발에 적합 |
| **DB · 인증** | PostgreSQL (Supabase) | 오픈소스 PostgreSQL 기반, 로그인 기능 내장, 행 단위 보안으로 사용자별 데이터 분리 |
| **AI** | Gemini API 무료 티어 (Flash) | 별도 비용 없이 사용 가능, 정해진 JSON 형식으로 답하는 구조화 출력 지원 |
| **캘린더 UI** | FullCalendar (MIT) | 주간·월간 보기와 드래그 이동을 직접 구현하는 수고를 덜 수 있음 |
| **CI · 테스트** | Vitest + GitHub Actions | 스케줄링 알고리즘을 단위 테스트로 검증, 푸시마다 자동 실행 |

## 6. 성공 기준과 리스크

### 🎯 성공 기준

- [ ] 자연어 10문장 중 **8문장 이상**이 확인 화면에서 수정 없이 저장된다
- [ ] 일주일치 할 일을 넣었을 때 **겹침 없이** 배치된다
- [ ] 배포된 URL에서 **로그인부터 자동 배치까지** 실제로 동작한다

### ⚠️ 리스크와 대응

| 리스크 | 대응 |
| --- | --- |
| 무료 API 호출 한도 초과 | 여러 줄을 한 번에 보내 호출 수 절약, 같은 입력은 결과 캐시, 초과 시 재시도와 안내 |
| AI가 날짜·시간을 잘못 해석 | 저장 전 확인 화면 제공, "내일" 같은 상대 날짜는 오늘 날짜를 함께 넘겨 해석 |
| 무료 티어 입력이 모델 개선에 쓰일 수 있음 | 민감한 내용 입력 자제 안내, AI 호출부를 분리해 로컬 오픈소스 LLM으로 교체 가능하게 설계 |
| 알고리즘이 복잡해져 일정 지연 | 1차는 단순 우선순위 배치, 작업 분할·재배치는 2차로 단계화 |
